# 自动发福袋设计

## 目标

为已连接巨量百应直播中控台的账号提供周期性自动发福袋功能。任务启动后立即执行一轮，随后按用户配置的间隔重复执行。默认间隔为 10 分钟。

## 用户流程

1. 用户先在“打开中控台”页面连接已登录的巨量百应账号。
2. 用户进入“自动发福袋”页面，设置循环间隔（分钟）。
3. 用户点击“开始任务”。页面显示运行状态，侧边栏显示运行标记。
4. 每轮任务打开“超级福袋”管理弹窗，在“待开始”列表中启动第一条可用活动。
5. 用户可点击“停止任务”终止后续轮次。

账号未连接时，开始按钮不可用，并显示“请先连接直播控制台”。间隔配置按本地账号持久化，默认值为 10 分钟。

## 自动化流程

后台复用当前账号的 Playwright 页面与平台实例，不创建额外浏览器会话。每轮按以下顺序执行：

1. 在直播中控台点击“超级福袋”。
2. 等待“管理超级福袋活动”弹窗可用。
3. 点击“待开始”页签。
4. 在活动表格中查找第一条包含可用“开始活动”按钮的记录。
5. 点击“开始活动”，等待页面确认活动已启动。
6. 关闭管理弹窗，使中控台恢复到下一轮可操作状态。

选择器优先依据可见文字、按钮语义、页签角色和表格行状态；页面生成的 CSS 类名只作为辅助条件。所有等待均设置有限超时，并响应任务停止信号。

## 任务模型

新增账号级 `auto-lucky-bag` 循环任务，沿用现有后台任务生命周期：

- 启动时校验平台能力、账号会话和间隔值，并立即执行第一轮。
- 一轮结束后等待配置间隔，再执行下一轮。
- 同一账号只允许一个自动发福袋任务运行。
- 用户主动停止或账号断开时，终止当前等待或页面操作并清理任务状态。
- 普通的单轮页面错误不会停止循环；任务记录错误后等待下一轮。

前端通过 IPC 启动和停止任务，并监听后台的停止事件，以保证页面状态与真实任务状态一致。

## 空列表与异常处理

“待开始”列表没有可启动活动时，本轮返回明确的“无待开始活动”结果，记录 WARN 日志，关闭弹窗并等待下一轮，不停止任务。

找不到“超级福袋”、页签、活动表格或关闭按钮时，本轮记录 ERROR，并尽力通过 Escape 或弹窗关闭按钮恢复页面。账号连接失效时停止整个任务，向前端发送停止事件。成功启动活动时记录 SUCCESS 日志。

## 界面

侧边栏新增“自动发福袋”，仅对巨量百应平台显示。页面采用现有设置页样式，包含：

- 循环间隔数字输入框，单位为分钟，默认 10，要求为正整数。
- 带播放或停止图标的主按钮。
- 简洁的当前状态与账号未连接提示。

页面不展示操作教程或页面 DOM 细节，具体执行结果进入现有运行日志。

## 代码边界

- 平台能力接口负责定义单轮“启动第一条待开始福袋”的操作。
- 巨量百应平台实现负责页面选择器、点击、等待与弹窗恢复。
- 循环任务负责调度、停止信号、单轮结果分类和日志。
- IPC 层负责将前端启停请求映射到账号会话任务。
- React 页面及状态 Hook 负责配置持久化、按钮状态与通知。

## 测试与验收

自动化测试覆盖：

- 任务启动后立即执行，后续按分钟配置换算后的间隔调度。
- 停止任务可取消等待，且不会再执行下一轮。
- 空列表返回可识别结果并保持任务运行。
- 单轮选择第一条可用活动并点击“开始活动”。
- 账号未连接、平台不支持和关键元素缺失时返回明确失败结果。
- IPC 启停通道和前端间隔校验。

静态验证运行 TypeScript 编译、Vitest 测试和 Vite 构建。人工验收使用已登录且已连接的巨量百应账号，确认首次立即启动、10 分钟默认间隔、空列表继续等待、停止按钮生效及运行日志内容。
