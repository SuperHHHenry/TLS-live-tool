# 观众账号：主播直播账号列表设计

## 目标

在“观众账号”页面维护多个主播直播账号。用户添加链接后，应用自动读取主播账号名称并检测是否正在直播；列表提供统一刷新状态的入口。已添加记录不可编辑，只能删除。该数据结构为后续“打开直播控制台时按顺序选择正在直播的房间”提供基础。

## 用户流程

1. 用户在新增区域粘贴抖音主播主页或直播间链接并点击“添加”。
2. 应用校验链接并调用 Electron 主进程检测，返回稳定账号标识、账号名称、当前直播状态及可进入的直播间链接（如可获得）。
3. 成功后将记录持久化并显示在列表；名称和链接均为只读。
4. 用户点击页面顶部“刷新”按钮，批量重新检测全部记录，保留原记录顺序并分别更新状态。
5. 用户点击删除并确认后移除记录；删除不会影响观众账号本身。

## 数据模型

`主播账号`记录至少包含：

- `id`：本地唯一 ID。
- `sourceUrl`：用户添加的原始链接，只读。
- `accountId`：解析出的平台账号 ID（可为空，用于兼容解析失败/旧数据）。
- `accountName`：平台返回的账号名称；解析前显示“读取中”。
- `liveStatus`：`live`、`offline` 或 `unknown`。
- `roomUrl`：最近一次检测到的直播间链接，可为空。
- `lastCheckedAt`：最近检测时间，可为空。

使用 Zustand persist 保存，增加版本迁移；检测状态属于缓存，可在刷新时覆盖，不影响记录身份。

## IPC 与检测

新增 viewer 主频道：单条检测和批量检测。主进程复用现有浏览器/会话能力，解析主播名称与直播状态，统一返回结构化结果；网络错误、页面结构变化或链接非法时返回 `unknown` 与可展示错误信息，不删除原记录。批量检测采用并发上限，避免一次刷新创建过多页面。

## 页面交互

- 顶部区域：输入框、添加按钮、刷新按钮；刷新期间按钮显示忙碌态并禁用重复点击。
- 列表行：账号名称为主标题，原始链接以截断文本展示，状态使用颜色标签和文字（直播中/未开播/暂无法判断），附最近检测时间。
- 行操作仅保留删除按钮；不提供重命名或编辑链接入口。
- 空列表展示引导文案；单条失败不阻塞其他记录更新。
- 删除使用确认对话框，确认后才调用持久化删除。

## 后续控制台衔接

本阶段不自动进入房间。后续点击“连接直播控制台”时，控制台读取列表并按保存顺序检查；找到首个 `live` 记录后将其 `roomUrl` 作为目标，让所有已添加观众账号进入该房间。若没有直播记录，保持未连接并提示用户。

## 验证

- 单元测试覆盖新增、持久化迁移、删除不可编辑、状态刷新成功/失败。
- UI 验证覆盖空列表、批量刷新忙碌态、混合状态列表和删除确认。
- 运行项目现有 lint/typecheck/test 命令。
